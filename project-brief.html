Project Brief — v0.1

Dialog with Poetگفتگو با شاعر

A Persian-language chat companion that lets you pick a classical or modern Persian poet, pick a subject, and talk — grounded in their real verses, not an impression of them.

prepared for reza.bazargan · 2026-09-11 · scope discussion, pre-build

01The idea, restated

Pick a poet — Hafez, Rumi, Saadi, Attar, Khayyam — pick a topic — love, loss, wine, justice, the news of the day — and have a conversation with them in Persian. The poet answers in their own idiom, drawing on their actual poems rather than a generic imitation, and the app pulls in supporting material (biography, historical context, the tradition they wrote in) to keep the dialogue grounded rather than drifting into vague wisdom-speak.

02My take

Verdict

Worth building. The idea itself — "chat with a poet" — already exists in English, generically, ungrounded. Nobody has done it in Persian, grounded in a real corpus, across multiple poets, framed by topic. That combination is a genuine gap, and you already found the hardest missing piece: a 132,500-poem corpus with retrieval infrastructure built in. The main risk isn't technical, it's editorial — making each poet sound like themselves and not like a chatbot wearing a costume, and being honest with users that they're talking to a simulation, not the poet.

03Who's already doing something like this

Searched for existing "talk to a Persian poet" products before scoping this. Everything found is English-first, single-poet (almost always Rumi), and ungrounded — the model free-associates in the poet's general "vibe" rather than quoting or citing real poems.

04What the original idea was missing

  • Grounding, not impression. Without retrieval over real poems, the model will confidently invent verses that sound right and aren't — the single biggest way a "poet chatbot" loses trust. Every reply should be able to point at the actual poem it's drawing from.
  • A distinct voice per poet. Hafez's ambiguous, wine-soaked ghazals, Rumi's ecstatic Masnavi, Saadi's moralist prose-poetry, Attar's allegorical Sufi tales, Khayyam's skeptical, carpe-diem quatrains — these need separate persona prompts and separate tone rules, not one "wise old poet" mask reused five times.
  • Context beyond the poems. Biography, the historical moment, the Sufi or literary tradition a poet worked in, well-known commentary on ambiguous verses — this is what turns "recite a couplet" into an actual dialogue that can explain, contextualize, and disagree.
  • An honesty layer. Persian poets, especially Hafez and Rumi, carry real spiritual weight for a lot of users. The app should be upfront that it's a simulation built from their words, not a channel to the person — a design and trust question, not just a technical one.
  • A distribution decision. A web app is the natural MVP, but a large share of the Persian-speaking audience lives inside Telegram (and, inside Iran, Bale/Eitaa) rather than opening a browser — worth deciding early since it changes the interface layer.
  • Persian-first UI, not just Persian replies. RTL layout, Persian typography (Vazirmatn or similar), and Nastaʿliq-adjacent visual language for the poet cards — the "communicate in Persian" requirement should shape the whole interface, not just the model's output language.

05The corpus you found

erfanbashar1/persian-poetry-ai-agent-plugin converts the entire Ganjoor library into an agent-ready database: 234 poets, ~132,500 poems, each poem a Markdown file with vocalized text, plain text, and a Persian summary, indexed for exact-line, Persian-semantic, and English-semantic search, exposed through an MCP server with local embeddings (Qwen3-Embedding, no external API needed for retrieval). Poetry is public domain; the Ganjoor compilation and summaries carry their own attribution requirement; the pipeline code is MIT.

This solves the hardest part — the corpus and retrieval layer — but it is a retrieval backend, not an app: no chat interface, no personas, no conversation memory, no topic framing. That's the layer this project adds on top.

06MVP — what to actually build first

Narrowed further: Rumi only for the first working version, text-only, Persian-only, web chat, for a small circle of friends. Right call — it lets you prove the CORE prompt, retrieval, and memory pipeline against one persona before multiplying to five.

  • Start with Rumi, add Hafez, Saadi, Attar, Khayyam once the pipeline holds. All five personas are already fully drafted (§12) — adding a poet after Rumi is mostly a data-scoping exercise, not new engineering.
  • Per-poet source list, curated not exhaustive: a handful of Ganjoor books per poet rather than everything they wrote — see §12 for the actual counts and where to be careful (Khayyam's two modern research editions especially).
  • Topic list has shifted from "literary" to "self-inquiry": تعلق (attachment), ترس (fear), خشم (anger), تنهایی (loneliness), مرگ (death), معنای زندگی and 18 more (§12) — closer to poetry-assisted reflection than a literature Q&A, which is a stronger, more differentiated product than §01's original framing.
  • A poem only when it's relevant, never invented: not every reply needs a verse, but any verse used must come from a verified retrieval source — the trust mechanism from §02 is intact, just not tied to "cite on every turn."
  • One visible disclosure: a persistent, unobtrusive label that this is an AI simulation grounded in the poet's work, not the poet.
  • Web chat UI, RTL, Persian throughout, picks up where you left off — no Telegram bot, no voice yet; cross-session memory is now in scope (§09).

Persistence — picking up the conversation tomorrow

New requirement, not in the original stack: Streamlit Community Cloud has no reliable persistent disk, so the conversation summary (§12's memory schema) needs a real store, plus a lightweight way to know which friend is talking. Simplest version: a name picker at login (no passwords needed for 5–6 friends) keying rows in a small hosted database.

What this actually costs

$20 comfortably covers this and then some. Streamlit, embeddings, and Supabase are $0 regardless of path. The only real spend is LLM calls — starting on Gemini's free tier makes the whole pilot free while you're building; switching to Claude Haiku 4.5 or Sonnet 5 once voice quality matters runs a few dollars a month at friends-group volume, so $20 is closer to a multi-month runway than a hard ceiling. If you want a genuinely $0 path throughout, an open-weight model (Qwen2.5 or Dorna, a Persian-tuned Llama) via a free-tier hosted endpoint is possible, but expect a real step down in how well it holds the persona's voice — worth it only if cost turns out to matter more than quality.

10Source material beyond the poems

Checked what Ganjoor actually holds per poet — three of your five wrote real prose alongside their verse, and it's the single best material for a dialogue bot, because it's the poet already talking in sentences instead of couplets. Worth pulling in on top of the verse corpus:

Update: use ganjoor/ganjoor-data instead of the third-party plugin as the content source — it's the official raw export straight from Ganjoor (240 poets, 135,319 entries, clean per-poet JSON), and since Ganjoor's data model doesn't structurally separate "poem" from "prose" — everything is a category/entry under a poet — it almost certainly already carries Fihi mā Fihi, Golestān, and Tazkirat al-Awliyā without needing a separate scrape. Confirmed Rumi's own poet.json profile lists all three of his prose works by name. Worth treating the plugin repo's embedding/search code as an optional reference rather than the source of truth for content.

Two more additions worth the effort, outside Ganjoor: a short, hand-written biography and symbol-glossary per poet (Hafez's می as divine love rather than literal wine, Rumi's نی as the soul cut from its source) — not a bulk source, just a page or two per poet that makes retrieved verses land correctly instead of literally. And for Rumi specifically, Maqālāt-e Shams — the recorded sayings of Shams-e Tabrizi, the companion whose arrival triggered Rumi's whole transformation — sits outside Ganjoor but is public domain and worth tracking down for the historical-context layer from §04.

Stayed away from modern commentary and Wikipedia-style write-ups on purpose — sticking to the poets' own prose and centuries-old companion texts keeps everything public domain and keeps the voice the poet's own rather than a modern scholar's paraphrase of it.

11Before you start building

Everything structural is decided (§08). What's left is a short list of concrete calls — mostly content and product, not technology — that are cheap to answer now and expensive to unwind after you've written code around them.

Prose in v1, or verse-only?
§10's prose works (Fihi mā Fihi, Golestān, Tazkirat al-Awliyā) are the best dialogue material you have, but they need different chunking and citation handling than a couplet. Decide whether v1 includes them or defers to Phase 2 — don't let this get decided implicitly by whatever the data pipeline happens to pull in.
How strictly must a reply be grounded? — answered, §12
Hard constraint when a poem is used (never invented, always from verified retrieval); soft on whether a poem appears at all — most turns won't have one.
Who writes the five persona prompts? — answered, §12
Done — all five drafted, in depth, with a shared CORE prompt underneath them.
Single-turn replies, or does the poet remember the conversation?
A poet who forgets what you said two messages ago feels like a search engine; one who remembers needs a real conversation-history design, even at friends-group scale.
Is the pilot actually private?
Streamlit Community Cloud's free tier gives you one private app with an email allowlist — decide now whether that's how you're gating it, since a public URL by default is a different privacy posture than you may want for a friends-only pilot.
Whose API key, and what's the monthly ceiling?
One account holds the LLM billing. Worth setting a hard spend cap on it (most providers support this) before your friends start using it, not after.
What tells you the pilot worked?
A concrete signal — friends coming back a second time, a specific poet getting used more than others, a "this felt off" moment you can point to — decided now so Phase 2 is a response to real usage rather than a guess.

12The persona document — and what it changes

Salek_Poet_Agent_Personas_FA is a real reframe, not an add-on, and a stronger product for it: the poet isn't answering questions about a topic, it's a mirror — a Socratic self-inquiry partner that uses the poet's worldview to help you see your own experience more clearly, never handing down a final answer. That moves this further from the generic "wisdom-bot" competitors in §03, not closer.

What it already gets right

A clean CORE / PERSONA / RUNTIME / SAFETY layering that matches §09's architecture exactly. A poem-grounding rule that's stricter than §06 originally asked for — quote only from VERIFIED_POEMS, or don't quote at all. Five genuinely distinct personas, each with its own "instinctive question" (Rumi: what remains when the story goes quiet; Hafez: are you fooling yourself with a beautiful name; Saadi: what changed in your behavior; Attar: what are you still clinging to; Khayyam: how do you know that), plus a "golden test" — one input, five different answers — to catch personas collapsing into the same voice. A structured memory summary (topic, experiences, observations, open hypotheses, open question, poems used) built for exactly the "continue tomorrow" requirement below. Real safety rules: no clinical diagnosis, redirect on self-harm, no encouraging dependency on the bot, explicit prompt-injection defense. A 10-point quality checklist and 8 adversarial test prompts to run before every release.

On scoping each poet to a handful of Ganjoor books

Yes — makes sense, and matches how the corpus should be scoped for a v1 anyway (§10). Curating 4–8 books per poet instead of their full Ganjoor catalog keeps the retrieval index small and every book hand-checkable before it's trusted. Attar's cut — Divān, Manteq al-Tayr, Mosibat-Nāmeh, Tazkirat al-Awliyā — is a good template: the most famous verse work, one more for thematic range, and the prose. One flag on Khayyam's four: Rubā'iyāt-e Khayyām be pazhuhesh-e Mirafzali and Sadegh Hedayat's Tarānehā-ye Khayyām aren't primary texts, they're modern scholarly curations of which quatrains are likely authentic — genuinely useful given how contested Khayyam's attribution is, but worth tagging with a different confidence value than the plain Robā'iyāt set, using the metadata schema the persona doc already defines in §9 of that document.

Cross-session memory, in practice

The persona doc's memory summarizer gives you the schema; §09's Supabase addition gives you where it lives. Concretely: one row per (friend, poet) holding the structured summary as JSON, loaded back in as CONVERSATION_SUMMARY on the next visit — the friend picks their name and the poet remembers where things were left, without replaying the whole transcript.
